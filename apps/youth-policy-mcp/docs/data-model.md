# 데이터 모델

## `policies`

원천 ID, 정책 본문, 분류, 기관, 지역, 구조화 조건, 신청·사업기간, 신청방법·URL·서류, 상태, 원천 수정·수집시각, 원문 해시를 저장합니다. `(source, source_policy_id)`는 유일합니다.

## `policy_conditions`

조건 종류, 연산자, 값·단위, 원문, 구조화 상태, 근거와 `manual_review`를 저장합니다. 자동 판정 가능한 값과 자유서술 원문을 분리합니다.

## `policy_versions`

정책별 순차 버전, 유효기간, 정규화 JSON, 원본 레코드, 필드 diff, 해시를 저장합니다. 현재 버전과 같은 원문 해시는 애플리케이션 계층에서 중복 버전화하지 않으며, 정책이 과거 상태로 실제 회귀한 경우에는 별도 시점 버전을 보존합니다.

## `policy_evidence`

정책 필드 경로마다 출처명·ID·URL, 근거 내용, 기준일·확인일, 신뢰수준, 해시와 충돌 메모를 저장합니다.

## `policy_legal_bases`

법령·조례 ID와 명칭, 조문, 시행·공포일, 기관, URL, 연결 방식·확실성·확인일을 저장합니다. 불확실한 자동 연결은 `manual_review=1`입니다.

## `sync_runs`

동기화 시작·종료, 상태, 신규·수정·동일·비활성·오류 건수와 비민감 요약을 기록합니다.

운영 저장 구현은 Worker와 함께 생성되는 SQLite 기반 `YouthPolicyStore` Durable Object입니다. 현재 정책·상세 묶음·버전·동기화 기록을 관계형 row로 보존하고 원천 단위로 강한 일관성을 유지합니다. D1 구현과 관계형 마이그레이션은 로컬·회귀 테스트용으로 유지됩니다. 도메인은 `PolicyRepository`에 의존하므로 저장 구현을 바꿔도 MCP·웹 규칙을 변경할 필요가 없습니다.
