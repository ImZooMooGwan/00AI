# 00AI NOTE 템플릿 센터

## 목적

공개 템플릿을 목적과 이용 대상별로 찾고, 문서 및 데이터베이스 구성을 미리 확인한 뒤 현재 워크스페이스에 독립 사본으로 복제한다. 문서 블록만 복제하던 기존 흐름을 데이터베이스 속성·샘플 항목·저장 보기까지 포함하도록 확장했다.

## 기능 범위

- 카탈로그 검색: 이름, 설명, 분야, 작성자, 태그 검색
- 탐색: 개인/팀/공공·행정 대상, 분야, 추천 여부 필터
- 정렬: 추천·인기, 최신, 이름, 평점
- 카드 정보: 이용 대상, 난이도, 준비 시간, 데이터베이스 포함 여부, 출처, 라이선스, 복제 수, 평점
- 미리보기: TipTap 문서 블록, 데이터베이스 속성, 선택지, 예시 행, 저장 보기, 출처와 이용조건
- 복제: 문서와 데이터베이스를 새 페이지에 원자적으로 저장. 데이터베이스 속성·행 사용자 값·저장 보기 설정을 독립 복사
- 기여 및 관리: 템플릿 버전, 공개 검토, 신고 및 신고 검토, 출처·라이선스 표시
- 공개 기여의 데이터 보호: 데이터베이스 구조와 보기 설정은 포함하되 예시 행은 기본 제외. 작성자가 별도 선택할 때만 최대 100행을 포함

## 신규 기본 템플릿

`0035_template_catalog_and_packages.sql`은 기존 공개 템플릿 메타데이터를 채우고 16개 템플릿을 추가한다.

- 주간업무일지, 프로젝트 실행 보드, 회의 액션아이템
- 정책사업 운영관리, 청년공간 월간 운영, 공간·행사 예약관리
- 프로그램·참여자 관리, KPI·성과지표 관리, 업무 인수인계 보드
- VOC·요청 처리관리, 자격증·학습 플래너, 정책홍보 콘텐츠 캘린더
- 팀 신규 구성원 온보딩, 여행 일정·예산 플래너
- 업무 절차·SOP 라이브러리, 시설·비품 점검 관리

각 템플릿은 편집 가능한 문서 구조, 사용자 정의 속성, 선택지, 가상 예시 행과 목적에 맞춘 태그를 제공한다. 실제 기관·개인 자료는 기본 데이터에 포함하지 않는다.

## 데이터/API 계약

- `GET /templates`: 공개 및 승인된 카탈로그 메타데이터
- `GET /templates/:id/preview`: 공개 승인 템플릿의 블록과 데이터베이스 패키지
- `POST /pages`: `templateId`를 전달하면 페이지·데이터베이스·행·보기·복제 통계를 단일 D1 batch로 저장
- `POST /templates`: `pageId`를 전달하면 원본 페이지의 데이터베이스 구조와 저장 보기를 캡처한다. `includeSampleRows`가 참인 경우에만 행을 캡처한다.

데이터베이스 패키지는 `{database:{title,view_type,layout_type,properties,rows,views}}` 구조다. 기존에 저장된 평면 `{title,properties,rows}` 형태도 읽어 하위 호환성을 유지한다. 복제는 공개·승인된 템플릿만 허용하고, 대상 워크스페이스 편집 권한을 확인한다.

## 배포 및 롤백 메모

- Cloudflare D1 migrations: `0035_template_catalog_and_packages.sql`, `0036_template_seed_views.sql`
- Worker 및 정적 클라이언트: 기존 NOTE 배포 workflow에서 함께 배포
- 롤백이 필요하면 배포 전 D1 백업을 확보하고, 데이터가 새 열에 기록된 후에는 단순히 이전 Worker만 배포하지 않는다. 구 Worker가 새 열을 무시하므로 템플릿의 새 복제 기능만 비활성화되며 기존 페이지 데이터는 삭제되지 않는다.
- 신규 템플릿은 고정 ID와 `INSERT OR IGNORE`를 사용해 재실행 시 중복 생성되지 않는다.

## 검토 항목

- SQLite에서 전체 마이그레이션 연속 적용 확인
- 각 신규 패키지의 JSON 파싱, 속성·행 수 확인
- TypeScript 타입 검사, production build, React hook-order guard 확인
- 출시 후 공개 템플릿 미리보기, 새 페이지 복제, DB 보기/행의 저장 여부를 배포 환경에서 점검
