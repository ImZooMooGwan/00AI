# 00AI Workspace: Notion 대안 벤치마킹 및 개발 기준

- 기준일: 2026-11-05
- 목표: 공공부문 팀이 문서와 업무 지식을 함께 만들고 재사용하는 협업 서비스
- 조사 상태: **데스크 리서치 및 현재 코드 매핑 완료 (100%)**
- 제품 구현 상태: **현재 운영 코드 기준 약 79.05%** (기능 영역 가중치 추정치이며, 실제 계정 간 공동 편집 및 전체 사용성 검증은 미완료)

> 조사 완료도와 제품 완성도를 구분한다. 이 문서는 비교 조사와 코드 대조를 마친 기준 문서다. 실제 공무원 사용자 인터뷰, 경쟁 제품 계정으로 동일 시나리오를 직접 수행하는 사용성 테스트, 운영 부하 측정은 별도 실증 단계다. 따라서 조사 완료도 100%는 “사전 조사 산출물 완성”을 뜻하며 제품의 Notion 동등성을 뜻하지 않는다.

## 1. 제품 방향과 운영 원칙

00AI Workspace는 문서 편집기만 복제하지 않는다. 팀이 페이지를 공동 편집하고, 업무용 데이터베이스와 템플릿을 만들고, 템플릿을 공개·복제해 개선하는 **공공 지식 협업 공간**으로 설계한다.

정식 출시 전 단계에서는 일상 업무 흐름을 빠르게 끝내는 편의성을 우선한다.

1. 가입 후 첫 문서 작성까지 짧게: 빈 문서, 템플릿, 초대, 최근 문서로 시작 경로를 단순화한다.
2. 반복 업무를 줄임: 템플릿 복제, 페이지 복제, 검색, 키보드 탐색, 알림을 기본 흐름으로 제공한다.
3. 협업을 중심에 둠: 실시간 편집, 멤버 초대, 댓글·멘션, 문서 변경 이력의 발견 가능성을 높인다.
4. 이관 비용을 낮춤: Markdown/HTML, DOCX/HWPX/PDF 등 현실적인 가져오기·내보내기 경로를 단계적으로 만든다.
5. 공개 템플릿 생태계를 운영 가능하게 함: 작성자, 출처, 라이선스, 버전, 복제 수, 신고·검수 상태를 데이터로 관리한다.
6. 보안·기관 정책은 별도 출시 게이트로 관리한다. 본 로드맵의 편의성 점수에 보안 적합성 점수를 섞지 않는다. 실제 대외비 자료를 다루는 승인 판단은 해당 기관의 정책·시스템 승인 절차를 별도로 통과해야 한다.

### 비교로부터 얻은 결론

- 문서와 데이터베이스는 하나의 페이지 모델에서 연결되어야 한다. 표만 삽입하는 것으로 데이터베이스 경험을 충족하지 못한다.
- 실시간 협업은 연결 자체보다 끊김 후 복구, 로컬 편집 상태, 저장 표시, 사용자 존재 상태가 제품 신뢰도를 결정한다.
- 검색·이동은 많은 페이지를 가진 팀에서 편집기 기능만큼 자주 사용된다.
- 업무용 서비스는 버전 복원, 첨부 정리, 초대·권한, 가져오기와 내보내기를 핵심 운영 기능으로 갖춰야 한다.
- 공개 템플릿은 단순한 정적 목록을 넘어 작성자·라이선스·버전·검수·신고·복제 귀속이 있어야 생태계로 운영할 수 있다.
- 외부 OSS를 통째로 가져오기보다는 상호작용과 데이터 모델을 벤치마킹하고, 현재 Cloudflare Workers/D1/Durable Objects 구조와 장기 유지보수 비용에 맞게 기능 단위로 구현한다.

## 4. 현재 00AI 구현 감사

현재 조사한 앱은 `apps/notion`의 React/Tiptap 프런트엔드, Worker API, D1 마이그레이션, Durable Object 기반 Yjs 문서방으로 구성되어 있다.

| 영역 | 점수 | 가중치 | 반영 점수 |
|---|---:|---:|---:|
| 편집기·블록 | 77% | 25% | 19.25 |
| 협업 | 78% | 20% | 15.60 |
| 탐색·검색 | 90% | 15% | 13.50 |
| 데이터베이스·업무 흐름 | 77% (기존 배포 76%) | 20% | 15.40 |
| 템플릿·이관 | 75% | 10% | 7.50 |
| 워크스페이스·운영 | 78% | 10% | 7.80 |
| **합계** |  | **100%** | **79.05%** |

기능 가중치는 협업 문서 제품에서 편집, 공동 작업, 탐색, 데이터 구조, 재사용, 팀 운영의 상대적 가치를 정한 제품 판단이다. 79.05%는 기능 구현 상태의 추정치다. 이번 배포는 성공했지만 실제 계정으로 저장 뷰 복귀와 다중 사용자 협업을 검증하지 못해 사용자 검증 완료율을 뜻하지 않는다.

2026-11-05 추가 반영: 사이드바 페이지별 메뉴에 열기·하위 페이지 만들기·즐겨찾기·링크 복사·최상위 이동·휴지통 이동을 연결했다. 메뉴는 화면 경계 안에 배치되며 바깥 클릭과 Escape로 닫힌다. 블록에 고유 ID를 저장해 블록 링크 복사와 블록 댓글 앵커를 제공하고, 마우스 드래그·키보드 단축키·작업 메뉴로 블록을 위아래로 이동한다. 데이터베이스 저장 뷰마다 행 열기 모드(측면/중앙/전체)를 보존한다. 사이드바의 워크스페이스·바로가기·페이지 섹션은 드래그로 재정렬하고 브라우저에 순서를 저장하도록 구현했으며, 이 순서 변경은 기기별 설정이다. 운영 브랜치 CI의 빌드·타입 검사·D1 마이그레이션·Worker 배포가 성공했다. 저장 뷰별 사용자 정의 속성 그룹 기능을 추가하고 로컬 및 CI 타입 검사·빌드, 원격 D1 마이그레이션 단계, Worker 배포가 성공했다. 신규 Worker 배포 `7c56507b-5335-4ef0-9f3f-bdf7489e76f0`(version `742fc58a-5d5c-40a5-a004-3c9afbdbe854`)가 100% 트래픽을 받는 것을 확인했다. 페이지 간 블록 이동은 대상 Yjs 문서 저장을 먼저 확인하고 원본 저장까지 확인한 뒤 마무리하도록 추가했으며, 신규 Worker 배포 `37165450-b08e-4d16-8df6-f6e09ecf3108`(version `68d3a38a-3b19-4867-99ef-6584854f5a83`)가 100% 트래픽을 받는다. 첨부파일이 포함된 블록은 원본 권한 연결을 유지하기 위해 이동을 차단하고, 블록 댓글은 원본 페이지에 남긴다. 로그인 화면은 확인했으나 실제 계정으로 동료 초대, 다중 사용자 편집, 블록 댓글 저장, DB 저장 뷰 복귀를 직접 검증하지 못했으므로 기능을 사용성 완료로 간주하지 않는다.

| P1-2 | 뷰·필터·정렬 | 테이블·보드·캘린더 뷰, 뷰별 필터와 다중 정렬, 사용자별 또는 워크스페이스 공유 뷰 저장 |
| P1-3 | 관계형 데이터 | 다른 데이터베이스와의 관계, 집계/롤업, 순환·삭제 동작 정의, 권한 필터링 |
| P1-4 | 가져오기/내보내기 | Markdown/HTML 가져오기·내보내기, PDF 출력이 구현됨. DOCX/HWPX는 레이아웃·표·첨부 호환성 검증을 통과한 범위와 제한사항 명시. 대용량·오류 파일에 재시도와 부분 실패 안내 |
| P1-5 | 템플릿 생태계 | 템플릿 등록/편집/버전, 공개/비공개/검수 상태, 작성자·출처·라이선스, 복제 수, 신고, 관리 검수, 원본 업데이트와 복제본 분리 |
| P1-6 | 실시간 복구 체험 | 재연결/오프라인/저장 대기 상태 표시, 네트워크 복구 후 변경 수렴, 중복 연결과 페이지 전환에서 편집 손실 없음 |

### P2 — 확장과 품질 향상

- 모바일 탐색·편집의 기능 동등성, 키보드/스크린리더 접근성, 한국어 날짜·입력기 처리.
- 공개 템플릿 갤러리의 검색·분류·인기/최신 정렬, 즐겨찾기, 평가·기여 가이드.
- HASA AI: 문서 요약·회의 결과/할 일 추출·초안 생성. 실행 전 대상 텍스트와 결과 반영 방식을 명확히 보여주고 사용자 승인 후 삽입한다.
- 관리자 운영 지표: 초대 수락, 주간 공동 편집, 검색 무결과, 템플릿 복제, 오류/재연결 지표와 기능 사용률.
- 성능: 대규모 페이지 트리/검색/댓글을 위한 쿼리 최적화, 긴 문서 편집 렌더링과 동시 접속 튜닝.

## 6. 효율성을 판단할 운영 지표

첫 베타가 아닌 정식 출시 후보를 판단할 수 있도록 출시 전 기준선을 만들고 파일럿 팀의 실제 수치로 목표를 조정한다.

- **첫 가치 도달 시간:** 가입부터 템플릿 복제 또는 첫 공동 문서 생성까지 걸린 시간.
- **초대 성공률:** 초대 발송 중 실제 합류 완료 비율 및 초대 완료까지의 시간.
- **협업 활성화:** 문서를 만든 팀 중 7일 안에 다른 사용자가 편집/댓글한 비율.
- **검색 효율:** 검색 후 문서 열기까지 걸린 시간, 검색 결과 없음 비율.
- **템플릿 재사용:** 템플릿 상세 열기→복제 비율, 복제 후 7일 내 수정/공동 작업 비율.
- **편집 안정성:** 충돌/복구 실패, 저장 대기 시간, 재연결 후 수렴 실패 건수.
- **운영 부담:** 초대/권한/자료 복구 관련 지원 요청 건수와 해결 시간.

초기에는 목표 수치를 임의로 고정하지 말고 파일럿 기준선을 2~4주 수집한 뒤 제품 목표와 알림 임계값을 정한다.

## 7. OSS 도입 정책

- 코드 복사 전에 각 저장소의 현재 `LICENSE`, 하위 디렉터리 라이선스, 모델/폰트/아이콘/샘플 데이터의 별도 조건, 상표와 콘텐츠 권리를 확인한다.
- AGPL-3.0 코드는 서비스 수정본을 네트워크로 제공할 때 소스 제공 의무 등 조건이 발생할 수 있으므로, 00AI에 코드 통합하기 전에 배포 형태와 의무를 검토한다.
- Outline의 BSL 1.1은 단순한 permissive 오픈소스 라이선스와 다르다. 이용 목적·제품 제공 방식·변경 허용 범위·전환 시점을 원문으로 검토한다.
- 기능 동작을 참고하는 것과 구현 코드를 복사하는 것을 구분한다. 우선은 자체 구현하고, 채택이 필요하면 의존성·업데이트·보안 수정·라이선스 고지를 포함한 OSS inventory를 만든다.
- 템플릿도 저작물이다. 출처·작성자·명시 라이선스가 확인된 템플릿만 배포하고, 사용자가 올린 템플릿의 게시·복제 권한을 약관/운영 절차와 함께 안내한다.

## 8. 권장 개발 순서

2026-11-05 운영 배포 기준으로 순서를 갱신한다.

1. **통합 시나리오 검증:** 실제 기관 계정 두 개로 초대·문서 공동 편집·블록 재배치·블록 댓글·저장 뷰 복귀를 검증한다. 로그인 가능한 세션이 없어 이 단계는 미검증이다.
2. **데이터베이스 보기 완성:** 기본 필터·정렬·그룹, 보기별 속성 표시·행 열기 모드, 사용자 정의 속성 그룹 기준을 구현하고 배포했다. 저장 뷰 전환·새로고침 후 복귀, 속성 삭제 후 처리, 계정 간 공유 동작은 실제 로그인 세션에서 확인해야 하므로 미검증이다.
3. **편집기 이동 기능:** 페이지 간 블록 이동을 대상 문서 저장 확인→원본 내용 재확인→원본 삭제 저장 확인 순서로 구현·배포했다. 첨부파일이 포함된 블록은 아직 지원하지 않으며, 블록 댓글은 원본 문서에 남는다. 실제 두 계정 협업 환경에서 동시 편집 충돌 시나리오는 미검증이다.
4. **사이드바 및 페이지 메뉴:** 섹션 재정렬과 페이지 재정렬을 새로고침 후에도 확인하고, 개인/공유 섹션 및 페이지별 메뉴의 빠진 조작을 채운다.
5. **문서 이관과 협업 안정성:** DOCX/HWPX 가져오기, 오프라인/재연결 복구, 변경 이력 비교·복원을 대표 업무 문서로 검증한다.
6. **반응형·접근성 실증:** 데스크톱·태블릿·모바일과 작은 창 높이에서 레이아웃, 스크롤, 메뉴·피크 동작을 확인하고 키보드/스크린리더 조작을 점검한다.
7. **파일럿 지표 수집:** 실제 업무 시나리오의 완료 시간, 초대 성공률, 검색 무결과, 편집 복구 실패율을 2~4주 측정한 뒤 다음 우선순위를 갱신한다.

각 단계는 수직 기능 단위로 끝낸다. UI만 만들고 API/권한/저장/오류 처리가 비어 있는 상태를 완료로 세지 않는다.

## 9. 개발 진행 프롬프트

아래 프롬프트를 저장소 작업 세션의 첫 지시로 사용한다.

```text
너는 00AI Workspace의 제품 엔지니어다. 목표는 Notion의 시각적 모사가 아니라 공공부문 팀이 문서를 함께 만들고, 업무 데이터를 관리하고, 검증된 템플릿을 복제·개선·공유하는 완성형 협업 서비스를 정식 출시 가능한 수준으로 만드는 것이다.

작업 원칙
- 저장소의 AGENTS.md, 기존 구조, 배포 방식, 현재 구현을 먼저 읽고 기존 스택과 호환되게 작업한다.
- 현재 앱은 apps/notion의 React/Tiptap, Cloudflare Worker, D1, Durable Objects/Yjs 구조를 우선 존중한다. 구조 변경은 운영 비용과 유지보수 이득이 분명할 때만 한다.
- 질문을 단계마다 하지 말고 문서와 코드에서 합리적 결정을 내려 연속 진행한다. 외부 계정/기관 승인/접근 불가능한 자격증명처럼 진행을 실제로 막는 사항만 필요한 작업을 끝까지 마친 뒤 마지막에 한 번에 묻는다.
- 비밀값을 코드·로그·문서·응답에 출력하거나 커밋하지 않는다. 이미 연결된 서비스/시크릿은 이름과 바인딩 상태만 점검하고 값을 노출하지 않는다.
- 보안 적합성을 제품 편의성 완료와 혼합하지 않는다. 실제 대외비 사용 가능성을 임의로 선언하지 않는다. 서비스 운영 효율성과 사용 편의성을 우선하되 권한 우회, 데이터 손실, 시크릿 노출 같은 기본 결함은 출시 차단 문제로 취급한다.
- 공개 템플릿은 출처와 이용 라이선스가 확인된 콘텐츠만 포함한다. Notion의 독점 템플릿이나 OSS 코드를 권리 확인 없이 복사하지 않는다.
- 구현 시 UI, API, 저장 모델/마이그레이션, 권한, 빈/오류/로딩 상태, 모바일 동작, 운영 지표를 함께 완성한다.

완성할 범위
1) 블록 편집: slash menu, 단축키, 문단 변환, checklist/toggle/callout/divider/link/image/file 등 공통 블록.
2) 페이지 탐색: 계층형 트리, 재정렬/이동, 최근 문서, 즐겨찾기, 빠른 이동.
3) 검색: 권한 필터가 적용된 제목+본문 전체 검색, 결과 하이라이트, 키보드 이동.
4) 협업: 워크스페이스 멤버/초대/역할 UI, 문서 댓글, @mention, 인앱 알림.
5) 변경 이력: 문서 버전 목록/비교/복원 및 복원 감사 흔적.
6) 업무 데이터베이스: table/board/calendar, 속성, 필터·정렬·그룹, 그 다음 relation/rollup.
7) 템플릿 생태계: 공공 업무 템플릿, 작성자·출처·라이선스·버전·검수·복제·신고 관리.
8) 가져오기/내보내기: Markdown/HTML 우선, PDF 및 DOCX/HWPX는 형식별 샘플 검증 후 단계적으로 지원.
9) HASA 보조 기능: 요약/정리/초안과 확인 후 삽입 UX.
10) 운영성: 설정, 상태 표시, 오류 진단, 핵심 사용 지표, 백업·복구 운영 절차.

진행 방식
- 우선 현재 코드와 이 문서의 P0/P1/P2 목록을 대조해 이미 구현된 부분을 재사용하고, 누락 기능을 사용자 가치·의존성·운영 영향으로 순서화한다.
- 각 수직 기능을 끝까지 구현한 뒤 다음 기능으로 넘어간다. 대규모 작업은 작동 가능한 단위로 나눠 커밋 가능한 상태를 유지한다.
- 자동화된 검사/빌드/형식 검증은 변경 위험에 맞게 실행한다. 사용자가 검사하지 말라고 하지 않은 경우에는 구현 후 타입 검사와 빌드를 확인한다. 외부 시스템에 실제 배포하거나 데이터에 파괴적 변경을 하기 전에는 기존 프로젝트의 명시된 배포 승인 절차를 따른다.
- 릴리스 의존성이나 최신 외부 API가 관련되면 공식 문서를 확인한다. OSS 코드를 복사하려면 최신 LICENSE와 하위 라이선스를 먼저 확인하고, 조건이 불명확하면 코드를 복사하지 않고 독립 구현한다.

완료 기준
- P0 사용 흐름이 UI부터 저장/권한/API까지 연결되고, 실제 오류·빈 상태가 설명된다.
- P1 데이터베이스·검색·가져오기 기능은 데이터가 새로고침/재접속 뒤에도 유지되며 팀 협업이 작동한다.
- 공개 템플릿은 재사용 권리, 출처, 버전, 운영자가 관리할 수 있는 상태를 가진다.
- 릴리스 전 회귀 시나리오를 실행하고 결과를 문서화한다. 기능 가중치 표를 실제 코드 상태에 맞춰 갱신하고, 구현되지 않은 것은 완료로 표시하지 않는다.
- 결과 보고에는 변경 파일, 실제 완료 범위, 실행한 검사와 결과, 남은 블로커, 외부 승인/자격증명 필요 여부를 간결히 적는다.
```
